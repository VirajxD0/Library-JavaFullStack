C. SERVLETS (Jakarta Servlet 6 — Week 2)
--------------------------------------------------------------------------------

    - What is Servlet? Java class handling HTTP requests, extends HttpServlet
    - Lifecycle: init() → service() → doGet()/doPost() → destroy()
    - Where: legacy/servlet/BookServlet.java

16. Annotations vs web.xml
    - @WebServlet("/legacy/books/*") vs <servlet> in web.xml

18. Session Management
    - HttpSession: setAttribute("currentUser"), getAttribute, invalidate() (logout)
    - Cookie: JSESSIONID

19. Filter vs Servlet vs Listener

20. JSP vs Servlet

G. HIBERNATE / JPA (Week 4-5)
--------------------------------------------------------------------------------
40. JPA vs Hibernate
    - JPA = spec (jakarta.persistence.*), Hibernate = implementation. Spring Data JPA uses Hibernate underneath.

41. Entity Mapping
    - @Entity @Table(name="users") @Id @GeneratedValue(IDENTITY=auto_increment) @Column(unique, nullable, length) @Enumerated(STRING)
    - Where: entity/User.java (7 entities)

42. Relationships (MOST IMPORTANT)
    - @ManyToOne(fetch=EAGER) + @JoinColumn(name="category_id") → books.category_id FK
    - @ManyToMany + @JoinTable(name="book_authors", joinColumns=@JoinColumn(name="book_id"), inverseJoinColumns=...) → join table
    - @OneToOne (User ↔ Member), @OneToMany (Category → Books if added)
    - Fetch: EAGER (load immediately) vs LAZY (load on demand) — why Book.category EAGER but User.member LAZY
    - Cascade: PERSIST/MERGE (save book → save authors if new)
    - Task: Draw categories → books → book_authors → authors diagram

43. JPQL vs Native SQL
    - JPQL: SELECT b FROM Book b WHERE b.title LIKE... (entity fields, not table columns)
    - Native: SELECT * FROM books ...
    - @Query with @Param
    - Where: repository/BookRepository.searchBooks()

44. Spring Data JPA Magic
    - Extends JpaRepository<Book, Long> gives findAll(), findById(), save(), delete(), paging
    - Derived query: findByTitleContainingIgnoreCase, findByAvailableCopiesGreaterThan, existsByUsername
    - Where: all 7 repositories

45. DDL Auto
    - update (alter table to match entity, dev), validate (prod), create-drop
    - Where: application.properties spring.jpa.hibernate.ddl-auto=update

46. Hibernate States
    - Transient (new), Persistent (managed, in session), Detached (after session close), Removed
    - Task: What state after bookRepository.save(new Book())?

47. N+1 Problem (advanced)
    - If LAZY and loop books → each getAuthors triggers query → fix via JOIN FETCH
    - Where: BookRepository.findByIdWithAuthors @Query LEFT JOIN FETCH

I. SPRING SECURITY + JWT + BCRYPT + RBAC (Week 5-6 — Modern, Most Important)
--------------------------------------------------------------------------------
55. Why Security? Manual HttpSession check fails if you forget a URL. Security is central FilterChain.

56. Spring Security 6 Concepts
    - SecurityFilterChain bean(s), Authentication, Authorization, Principal, GrantedAuthority, SecurityContextHolder
    - FilterChainProxy → DelegatingFilterProxy → chain of filters
    - Where: security/SecurityConfig.java (2 chains)

57. Two Chains in This Project
    - Order(1) /api/** → STATELESS + csrf disable + JWT filter, permit /auth/**, authenticated for rest, 401 JSON
    - Order(2) /** → STATEFUL + formLogin, permit /, /login, /register, hasRole ADMIN for /books/add etc
    - Task: Explain difference STATELESS vs STATEFUL, why two chains needed for JSP session + REST JWT.

58. Authentication Flow (JSP)
    - GET /login → login.jsp form → POST /login (username/password) → DaoAuthenticationProvider → UserDetailsService.loadUserByUsername → PasswordEncoder.matches → success → defaultSuccessUrl /dashboard → session cookie JSESSIONID

59. Authentication Flow (REST JWT)
    - POST /api/v1/auth/login {username,password} → AuthService → authenticationManager.authenticate() → UserDetailsService + BCrypt check → JwtTokenProvider.generateToken() → return JwtResponse{token} → client stores → every API request header Authorization: Bearer <token> → JwtAuthenticationFilter validates → sets SecurityContext → controller sees authenticated

60. BCryptPasswordEncoder
    - Adaptive hashing, salt per password, one-way, strength 10 (2^10 rounds). Why not MD5? MD5 fast + unsalted → rainbow table.
    - Where: SecurityConfig.passwordEncoder(), AuthServiceImpl.encode(), DataInitializer.encode("Admin@123") → hashes start $2a$10$

61. UserDetailsService
    - Bridge between your User table and Security. Must return org.springframework.security.core.userdetails.User with username, password (hashed), authorities (list of SimpleGrantedAuthority("ROLE_ADMIN"))
    - Where: security/UserDetailsServiceImpl.java — supports login via username OR email

62. JWT (JJWT 0.12.5)
    - Structure: header.payload.signature (Base64Url). Header {alg:HS256}, Payload {sub:username, iat, exp}, Signature HMAC SHA256(secret)
    - Generation: Jwts.builder().subject(username).issuedAt(now).expiration(expiry).signWith(key).compact()
    - Validation: Jwts.parser().verifyWith(key).build().parseSignedClaims(token) → throws if tampered/expired
    - Extraction: getSubject()
    - Where: security/JwtTokenProvider.java — secret from application.properties jwt.secret (base64 32B), expiration 86400000ms=24h
    - Task: Decode a token at jwt.io and identify parts.

63. JwtAuthenticationFilter
    - Extends OncePerRequestFilter, getJwtFromRequest() reads "Bearer " prefix, validateToken(), load UserDetails, create UsernamePasswordAuthenticationToken, setDetails, SecurityContextHolder.getContext().setAuthentication()
    - Why OncePerRequestFilter? Ensures once per request even with forwards.
    - Where: security/JwtAuthenticationFilter.java — registered addFilterBefore(UsernamePasswordAuthenticationFilter)

64. RBAC (Role-Based Access Control)
    - Enum Role.ROLE_USER / ROLE_ADMIN, @Enumerated(STRING) stored as string.
    - Config: .hasRole("ADMIN") → expects ROLE_ADMIN, .hasAnyRole("USER","ADMIN")
    - JSP: ${pageContext.request.isUserInRole('ROLE_ADMIN')} to hide buttons/menu
    - Task: Add new ROLE_LIBRARIAN and restrict /categories/**

65. Authorization Decisions
    - URL-based in SecurityConfig vs Method-based @PreAuthorize("hasRole('ADMIN')") on service methods (EnableMethodSecurity)
    - Demo hidden: Book.RestController could add @PreAuthorize, but currently URL-based.

66. CSRF
    - Cross-Site Request Forgery. For JSP session, POST needs _csrf hidden field. This project disables CSRF for demo (SecurityConfig csrf.disable()) with comment. In production enable and add <input type="hidden" name="${_csrf.parameterName}" value="${_csrf.token}"/>
    - Why disabled for /api/**? JWT stateless already protected (token not cookie).

67. Logout & Session
    - /logout → invalidateHttpSession(true) → deleteCookies JSESSIONID → redirect /login?logout
    - For JWT, logout is client-side: delete token from localStorage (stateless no server logout unless blacklist).

68. Error Handling for Security
    - API: authenticationEntryPoint returns 401 JSON; Web: accessDeniedPage /403 → error/403.jsp
    - GlobalExceptionHandler handles BadCredentialsException → 401, AccessDeniedException → 403

69. Password & User Flow
    - Register: RegisterRequest @Valid → check existsByUsername/email → encode → save User + optional Member → UserDTO (no password)
    - Login: LoginRequest → authenticate → generate JWT → JwtResponse
    - Where: service/impl/AuthServiceImpl.java, controller/AuthController + rest/AuthRestController

J. ADDITIONAL CONCEPTS
--------------------------------------------------------------------------------
70. Maven
    - pom.xml: parent spring-boot-starter-parent (version management), dependencies (web, jpa, security, jjwt, h2, mysql, jasper, jstl), build plugins (spring-boot-maven-plugin, maven-war-plugin)
    - Commands: mvn clean install, mvn spring-boot:run, mvn clean package
    - Scope: provided (jasper only at runtime), runtime (h2, mysql)

71. DTO & Mapper Pattern
    - DTO hides internal entity (password), flattens relations (categoryName instead of Category object), validation.
    - Mapper: toDTO() / toEntity() manual mapping (vs MapStruct). Why manual? Interview easy to explain.
    - Where: dto/*, mapper/* (BookMapper uses AuthorMapper)

72. Layered Architecture
    - Controller → Service (business + @Transactional) → Repository (data) → DB
    - Why interface + impl? SOLID, mock in tests, swap impl.

73. Validation
    - Bean Validation: @NotBlank, @Email, @Size, @Min with messages → triggers MethodArgumentNotValidException

74. Bootstrap 5 + JSP Integration
    - CDN bootstrap.min.css, table, card, badge, alert, btn, grid row/col-md-*
    - Where: all JSPs header includes Bootstrap, dashboard stat cards

75. Profiles (dev/prod)
    - Spring reads application.properties then application-{profile}.properties. Active profile dev → H2, prod → MySQL. Switch via spring.profiles.active=prod or -Dspring.profiles.active=prod

76. Deployment
    - Embedded Tomcat: java -jar target/*.war (Spring Boot) vs External Tomcat: copy war to webapps/
    - WAR packaging for JSP (JSP needs war + jasper). JAR would not support JSP well.

77. Testing Strategy
    - Unit: service with mocks, Repository with @DataJpaTest, Controller with @WebMvcTest + @WithMockUser, Security with spring-security-test
    - Manual: Postman for JWT, browser for JSP

78. Git & .gitignore
    - Ignore target/, .idea, .settings, .DS_Store, *.log
